Modify CommunityPreviewView so that after confetti celebration, the user navigates directly to the community hub (with welcome overlay) instead of dismissing back to discovery.

The NavigationStack lives in ContentView wrapping HubsView. CommunityPreviewView is a destination pushed onto that stack via `.navigationDestination(for: HubsRoute.self)` on HubsView. To navigate forward to CommunityHubView from within CommunityPreviewView, use `.navigationDestination(isPresented:)` — this pushes a new view onto the same NavigationStack without needing access to the path binding.

Implementation steps:

1. Add `@State private var navigateToHub = false` to CommunityPreviewView

2. Add `.navigationDestination(isPresented: $navigateToHub)` modifier to the view body, presenting `CommunityHubView(communityID: communityID)`:
```swift
.navigationDestination(isPresented: $navigateToHub) {
    CommunityHubView(communityID: communityID)
}
```

3. Change the `onSubscriptionComplete` callback (lines ~178-184) from:
```swift
onSubscriptionComplete: {
    showTiers = false
    Task { @MainActor in
        try? await Task.sleep(for: .milliseconds(300))
        dismiss()
    }
}
```
to:
```swift
onSubscriptionComplete: {
    showTiers = false
    Task { @MainActor in
        try? await Task.sleep(for: .milliseconds(300))
        navigateToHub = true
    }
}
```

This keeps the 300ms delay (for tier sheet dismiss animation to complete per Phase 04-02 decision), then pushes CommunityHubView onto the NavigationStack. The user lands on the community hub where the welcome overlay (from Task 1) appears on first entry. The back button from CommunityHubView returns to CommunityPreviewView, and from there back to discovery — standard NavigationStack behavior.

Do NOT modify CommunityCardView, CommunityHeroCardView, or any discovery views. The navigation change is scoped entirely to the post-confetti callback in CommunityPreviewView.
