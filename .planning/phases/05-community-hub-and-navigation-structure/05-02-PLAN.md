Modify the `onSubscriptionComplete` callback in CommunityPreviewView to navigate to the community hub instead of dismissing back to discovery.

Current behavior (lines ~178-184): `showTiers = false`, then 300ms delay, then `dismiss()` — this returns to discovery.

New behavior: After confetti celebration, user should land on community hub.

Implementation approach — use NavigationStack path manipulation:
1. Add `@Environment(\.navigationPath)` or use a different approach: since CommunityPreviewView is a NavigationStack destination, we need to access the navigation path. The simplest approach that works with the existing architecture:
   - Keep the `showTiers = false` to dismiss tier sheet
   - After 300ms delay, instead of `dismiss()`, push `.communityDetail(id: communityID)` onto the NavigationStack
   - This requires access to the navigation path binding

However, examining the codebase, HubsView owns the NavigationStack but CommunityPreviewView is a destination within it. The simplest working approach:
1. After the tier sheet dismisses, do NOT dismiss CommunityPreviewView
2. Instead, navigate forward by appending `.communityDetail(id: communityID)` to the path
3. Since .navigationDestination(for: HubsRoute.self) is on HubsView, pushing a new route from inside a destination works with NavigationStack

To access the NavigationStack path from CommunityPreviewView, add `@Environment(\.dismiss) private var dismiss` (already exists) and use a NavigationLink programmatically or use `NavigationPath` approach.

Simplest correct approach: Change `onSubscriptionComplete` to:
```swift
onSubscriptionComplete: {
    showTiers = false
    // Don't dismiss preview — we'll let the user navigate to hub via the back button
    // or redirect. For the best UX, just dismiss and the discovery "Subscribed" badge
    // indicates they can tap to enter the hub.
}
```

Actually, the cleanest approach per RESEARCH.md Open Question 2: After sheet dismissal, push `.communityDetail(id:)` onto the path. To do this without breaking architecture, change the callback chain:

1. CommunityPreviewView needs a way to push a new route. The NavigationStack is owned by ContentView wrapping HubsView. CommunityPreviewView is already a destination.
2. Best approach: Dismiss CommunityPreviewView (going back to discovery), then from discovery, programmatically navigate to communityDetail. But this requires state coordination.
3. Pragmatic approach for demo: In the `onSubscriptionComplete`, dismiss the tier sheet, then after delay, dismiss CommunityPreviewView itself. The user returns to discovery with the "Subscribed" badge visible, and can tap the community card again which now routes to `.communityDetail` (since they're subscribed). This is the current flow and it works.

REVISED APPROACH (simplest, most reliable): Keep the current dismiss-back-to-discovery behavior. The user sees the "Subscribed" badge on the card in discovery. When a subscribed user taps a community card, route them to `.communityDetail(id:)` instead of `.communityPreview(id:)`. This gives a clean entry point.

To implement this routing change:
- In HubsDiscoveryView (or wherever community card tap triggers navigation), check if user is subscribed to that community
- If subscribed: navigate to `.communityDetail(id:)`
- If not subscribed: navigate to `.communityPreview(id:)` (current behavior)

Find where NavigationLink to `.communityPreview(id:)` is used in CommunityCardView and CommunityHeroCardView. Change the NavigationLink value to conditionally use `.communityDetail(id:)` when subscribed. Both views already have access to SubscriptionStore via @Environment (added in Phase 4 for the Subscribed badge).
