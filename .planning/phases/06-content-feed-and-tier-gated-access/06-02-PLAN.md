2. **ContentFeedView.swift** — `struct ContentFeedView: View` taking `community: Community` and `filterToVideos: Bool = false`.
   - `@State private var viewModel: ContentFeedViewModel?` — initialized lazily in .onAppear (matches project pattern for deferred @Environment access)
   - `@Environment(SubscriptionStore.self) private var subscriptionStore`
   - `@State private var showTierSheet = false`

   **CRITICAL:** This view must NOT have its own ScrollView. It renders as a plain VStack/LazyVStack that participates in the outer CommunityHubView's ScrollView. Per RESEARCH.md Pitfall 3: nested ScrollView inside paged TabView inside LazyVStack inside ScrollView creates janky scroll.

   Body structure:
   - If viewModel is nil, show ProgressView
   - Otherwise: VStack(alignment: .leading, spacing: 0) containing:
     a. CollectionFilterPicker bound to viewModel.selectedCollection (only if NOT filterToVideos mode — videos section shows all YouTube posts without collection filter)
     b. LazyVStack(spacing: 16) iterating viewModel.filteredPosts with ForEach, rendering PostCardView for each post

   **Tier access check per post:**
   - Compute userTierIndex: find subscriptionStore.currentTier(for: community.id) UUID in community.tiers array to get index. If nil (not subscribed), userTierIndex = nil.
   - `let isLocked = !viewModel.canAccess(post: post, userTierIndex: userTierIndex)`
   - `let requiredTierName = viewModel.tierName(for: post.requiredTierIndex)`
   - Pass isLocked, requiredTierName, and onUpgrade closure to PostCardView
   - onUpgrade sets showTierSheet = true

   **TiersBottomSheet presentation:**
   - `.sheet(isPresented: $showTierSheet) { TiersBottomSheet(community: community) }` — reuses existing Phase 4 upgrade infrastructure per user decision

   **Padding:** Add .padding(.horizontal, 16) on the LazyVStack for card inset. Add .padding(.bottom, 32) at bottom for scroll breathing room.

3. **CommunitySectionPager.swift** — Replace the EmptyStateView placeholders:
   - `.posts` case: `ContentFeedView(community: community)`
   - `.videos` case: `ContentFeedView(community: community, filterToVideos: true)`
   - Keep `.discussions` and `.faq` EmptyStateView placeholders unchanged (Phase 7)

   Per RESEARCH.md Pattern 3: the .videos section reuses ContentFeedView filtered to youtubeLink posts only, avoiding duplicate view code.

Register ContentFeedView.swift and CollectionFilterPicker.swift in project.pbxproj under the Feed group.
